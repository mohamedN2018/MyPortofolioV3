## 2. Search crawler access policy

`robots.txt` (generated by `core/brand_views.robots_txt`):

```
User-agent: *
Allow: /
Disallow: /admin/
Disallow: /dashboard/
Disallow: /api/
Disallow: /search/
Disallow: /set-language/
Disallow: /i18n/
Sitemap: https://mohamednabilpro.deplois.net/sitemap.xml
```

* All search and AI-search crawlers (Googlebot, Bingbot, OAI-SearchBot, PerplexityBot, Claude-SearchBot, …) can read public pages. No crawler-specific blocks were added by the site.
* **Important:** Cloudflare currently prepends its *managed* robots.txt content to the response (observed live: `Content-Signal: search=yes,ai-train=no,use=reference` and `Disallow` rules for some training crawlers such as Amazonbot). That is a Cloudflare dashboard setting (Security → Bots → "Manage AI crawlers / robots.txt"), not part of the code. It allows search and blocks AI *training*. Leave it as-is if you want to allow AI search but not training; if you want AI assistants to quote you, make sure the AI-search user agents are not blocked there. I did not change any Cloudflare settings.
* Private areas (admin, dashboard, API, internal search) are disallowed **and** protected server-side (robots.txt is not a security control).

## 7. Known limitations

* No guarantee of rankings, Knowledge Panel, AI Overview or chatbot mentions.
* "Mohamed Nabil" is a common name. Disambiguation depends on consistent profiles and on external sites linking back to yours.
* The domain is a subdomain of `deplois.net` (a hosting platform). A personal domain (e.g. `mohamednabil.dev`) is a stronger long-term identity signal; `SITE_URL` makes switching a config change.
* Language variants use `?lang=` rather than `/ar/` prefixes (kept to avoid a risky URL migration). Google supports this with hreflang + canonical.
* `llms.txt` is a community convention, not a standard used for ranking.
* Articles: the 3 existing blog posts in the local DB look like seed content. I did **not** write new articles on your behalf, because publishing invented experience would conflict with the authenticity requirement. Suggested topics, written by you: "Building Seshat: offline-first POS with SQLCipher and RS256 licensing", "Deploying Django + Celery on Dokploy", "Bilingual (AR/EN) Django sites without URL prefixes".
